How This Algorithm Works
Rule-Based Classification

Overview

The Rule-Based Classifier is the first algorithm TalaSaAI runs for every student. It reads the student's pre-assessment score and applies a simple set of rules to decide which reading difficulty level the student should start at.

Step-by-Step Process

📝
1 · Input
The system reads the student's pre-assessment score (0–100). This is a quiz taken by the student before starting any reading sessions. It measures their baseline reading readiness so the system can place them at the right starting level.
⚙️
2 · Normalize
The raw score is clamped to the valid 0–100 range and rounded to the nearest integer. Any value below 0 is treated as 0, and any value above 100 is treated as 100. This prevents edge cases from breaking the rule logic.
🔍
3 · Threshold Check
The normalized score is compared against three fixed thresholds. The matching threshold determines the student's Class Level, which controls which difficulty of reading passages they will receive.
✅
4 · Result
The system assigns a class level: Easy, Moderate, or Hard. This level is stored in the student's profile and used to filter all reading passages shown to that student.

Threshold Ruler

🟢 Easy  (0 – 59)
🟡 Moderate  (60 – 79)
🔴 Hard  (≥ 80)

Rule Logic (Pseudo-Code)

# TalaSaAI — Rule-Based Pre-Assessment Classifier function classify(raw_score): score = clamp(raw_score, 0, 100) # Step 2: normalize if score >= 80: # Step 3: threshold check return "HARD" elif score >= 60: return "MODERATE" else: return "EASY"
💡 Why rule-based? Rules are fully transparent and auditable. A teacher can always verify exactly why a student received a specific class level — just check the score against the thresholds above. There is no hidden computation.

Overview

The SVM Passage Classifier is a machine learning model that reads a passage of text and automatically predicts how difficult it is (Easy, Moderate, or Hard). This removes the need for teachers to manually tag every passage.

Step-by-Step Process

📄
1 · Input
A raw text passage is submitted to the classifier. This can be a passage from the library or any custom text pasted into the text area above.
🔬
2 · Feature Extraction
The text is analyzed to extract four linguistic features that describe complexity: average sentence length, average word length, type-token ratio (vocabulary richness), and total word count. These numbers become the input to the model.
🤖
3 · SVM Model
A Support Vector Machine (SVM) — trained on hundreds of pre-labeled passages — maps the extracted features to a predicted difficulty class. SVM finds the optimal mathematical boundary that separates Easy, Moderate, and Hard passages in feature space.
📊
4 · Output & Confidence
The model outputs a predicted label (Easy / Moderate / Hard) and a confidence score (0–100%). High confidence means the passage clearly fits that level. Lower confidence means it sits near the boundary between two levels.

Features Extracted from the Passage

📏
Sentence Length
Average number of words per sentence. Longer, more complex sentences are typically associated with harder reading levels.
🔤
Word Length
Average number of characters per word. Passages with longer words tend to use more complex or academic vocabulary.
📚
Type-Token Ratio
The ratio of unique words to total words. A higher ratio indicates more varied vocabulary, which generally makes reading harder.
🔢
Word Count
Total number of words in the passage. Longer passages require more sustained reading effort and concentration.
💡 What is a Support Vector Machine? An SVM is a supervised machine learning algorithm. It was trained on a set of reading passages that experts already labeled as Easy, Moderate, or Hard. It learned the patterns in those labels and now applies them to new passages automatically — without any human tagging needed.

Overview

The Recommendation Engine runs at the end of each week. It looks at how well a student performed across all their reading sessions that week and recommends a new difficulty level for the following week — either keeping the current level or moving the student up or down.

Step-by-Step Process

📋
1 · Input
The engine gathers all of the student's session scores for the current week and computes a weekly average score (0–100%). This single number summarizes overall performance for that week.
📏
2 · Threshold Check
The weekly average is checked against the student's current level, not just a single raw score. That means the outcome can change depending on the scenario: an Easy student at 60% or above moves up to Moderate, a Moderate student at 80% or above moves up to Hard, and a Hard student below 80% moves down to Moderate.
🎯
3 · Output
The engine sets nextClassLevel — the difficulty of passages the student will see next week. If the recommendation is applied, the student's class level is automatically updated in their profile.

Why Average Over a Full Week?

A single session score can be skewed by a bad day, distraction, or an unusually hard passage. Averaging across the entire week gives a more reliable picture of the student's actual performance before the system adjusts their level.

Recommendation Logic (Pseudo-Code)

# TalaSaAI — Weekly Recommendation Engine function recommend(weekly_session_scores, current_level): avg = sum(weekly_session_scores) / len(weekly_session_scores) if current_level == "EASY": if avg >= 60: next_level = "MODERATE" else: next_level = "EASY" elif current_level == "MODERATE": if avg >= 80: next_level = "HARD" elif avg >= 60: next_level = "MODERATE" else: next_level = "EASY" else: if avg >= 80: next_level = "HARD" else: next_level = "MODERATE" apply_to_student(next_level) # update class level for next week return next_level

Recommendation Status

✅
Applied
The student's class level has been updated. Starting from their next session, they will receive passages at the new difficulty level.
⏳
Not Applied
The week is still in progress, or the teacher has reviewed the recommendation and decided to keep the current level manually. The student's level has not changed yet.
